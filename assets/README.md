# Art

## Files the game looks for

| file | when it is shown |
|---|---|
| `intro-1.png` | first intro beat — "I'm never going to make the show at this rate" |
| `intro-2.png` | second intro beat — "I've gotta get out of here!!" |
| `stage-1.png` … `stage-7.png` | one per stage, in order |
| `reference.png` | not shown; the character reference for `npm run art` |

Every one of these is optional. Until a file is here the game shows a labelled
holding frame in its place, so the whole thing is playable with this directory
empty. The server only hands the client a path when the file is really on disk,
so a missing image is a placeholder rather than a 404.

## Export spec

**Square, 2048×2048, PNG, on a flat `#191919` background.**

`#191919` is the page's own background colour, so a square export sits in the
stage mount with no visible edge — the art ends and the wall carries on. The
frame renders `aspect-ratio: 1/1; object-fit: cover`, so a portrait or landscape
export gets centre-cropped and loses its top and bottom.

## Generating them

`npm run art` writes the seven stage dioramas from the prompts in `stages.js`.
Character consistency comes from the reference image: drop the punk in as
`reference.png` — `cell.png` from the jailbreak repo is the obvious choice — and
every stage is generated against it. With no reference present, stage 1 is
generated cold and becomes the reference for the other six.

The two intro stills are not generated by that script; they are hand-made.
